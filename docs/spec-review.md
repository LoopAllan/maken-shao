# Master Specification 審查與 v0.1 補充建議

> 審查對象：`Maken-Shao-Project-Specification.md` v0.1
>
> 範圍：本文件只提出補充與決策建議；不覆寫原始 Master Specification。

## 摘要

原規格清楚定義了「可驗證中文知識庫」的目標、禁止腦補的原則與第一版技術限制。不過，若要讓資料可長期維護並能以離線網站穩定呈現，仍需補齊資料契約、來源模型、引用規則、驗證責任邊界與離線行為等細節。v0.1 將以下建議落實為文件、JSON Schema 與本機驗證腳本。

## 發現與建議

| 類別 | 規格缺口／風險 | v0.1 補充決策 |
| --- | --- | --- |
| 資料容器 | 原規格列出 `*.json`，但未定義檔案頂層是陣列還是物件，亦未定義 metadata。 | 各內容檔採用頂層陣列；`site.json` 為網站 metadata 物件。Schema 描述每筆內容資料。 |
| 共通欄位 | 已列出基本欄位，但未定義字串長度、日期格式、可否 `null`、額外欄位政策。 | 必填欄位不得為 `null`；採 Draft 2020-12 JSON Schema、`additionalProperties: false`、ISO `YYYY-MM-DD` 日期格式與長度限制。 |
| 來源資料 | 未定義來源應有欄位，無法確定 `sourceIds` 對應什麼。 | `sources.json` 的每筆來源具有唯一 `id`、標題、來源類型、出版者／作者、URL 或書目資訊、來源層級、存取／出版日期與註記。 |
| 引用精度 | 只有「保留來源」，但未規定引用應指向哪個頁碼、章節或網址片段。 | 每項 `sourceIds` 必須存在；實際資料在 `verificationNote` 記錄頁碼、章節、時間戳或 URL fragment。後續可升級為結構化 citation 陣列。 |
| 版本與地區 | `gameVersion`、`region` 尚未有受控值；兩版本共用資料的證據門檻未定義。 | `gameVersion` 固定為三種 enum。`region` 以 ISO 3166-1 alpha-2（或 `unknown`）表達。只有同一論述經兩個版本證據確認才可用 `both-confirmed`。 |
| 查證狀態 | `confidence` 與 `verificationStatus` 可被矛盾使用，例如官方來源卻標未查證。 | Schema 限制各自 enum；驗證器額外要求 `verified` 不能搭配 `unverified`，而 `conflicting` 必須有非空查證說明。 |
| 未知／衝突 | 原規格允許未知，但沒有固定呈現方式。 | 未知資料應使用 `not-verified`、`unverified`，並在 `verificationNote` 寫明「目前查無可靠來源」或待查範圍；不可用推測內容填補。 |
| 劇透 | 有劇透開關需求，沒有資料層旗標與預設行為。 | v0.1 加入可選 `spoiler` boolean，前端預設折疊含此標記的內容；開關只改變閱讀顯示，不改寫資料。 |
| 完整顯示（2026-07-16 產品決策） | 原規格要求劇透開關，與最新方向衝突。 | 以最新使用者決策為準：移除所有 UI 防劇透機制，搜尋、角色、流程、來源與結局區塊均預設直接顯示；資料、schema 與驗證器也刪除 `spoiler`／`spoilerLevel`。 |
| 內容型別 | 角色、流程、Knowledge、結局與 Boss 的專屬欄位未定義。 | 每類型各有 schema；v0.1 只納入最小、安全的描述欄位，避免把未研究的遊戲規則硬編碼。 |
| Placeholder | 示例資料規則未被原規格形式化，容易混入看似真實的內容。 | v0.1 以 `isPlaceholder: true` 和標準警語管理示範資料；任何示範文字必須含「示範資料，非正式攻略內容」。 |
| 離線行為 | 「離線可瀏覽」未說明資料載入策略。瀏覽器直接以 `file://` 開頁會阻擋 `fetch()`。 | HTML 內含可閱讀的骨架；資料載入器會嘗試 `fetch`，失敗時清楚提示以本機靜態伺服器開啟。完整驗證與搜尋資料載入在 HTTP 靜態伺服器環境可運作，且無外部 CDN。後續可評估 build-time inline JSON。 |
| 瀏覽器支援 | 未定義支援範圍。 | v0.1 目標為現行 evergreen browsers；不使用需要網路的 API 或第三方 runtime。 |
| 搜尋 | 未定義索引範圍、結果排序及跨版本處理。 | v0.1 以本機載入的 JSON 建立簡易、不送出資料的文字搜尋；結果顯示資料類別與版本。未載入資料時保留明確空狀態。 |
| 可及性 | 僅列「無障礙設計」，未列驗收標準。 | 使用語意 landmark、鍵盤可操作按鈕、可見 focus、`aria-expanded`、跳至主內容連結、足夠對比；完整 WCAG 稽核列為後續工作。 |
| 內容授權 | 未規定文字、截圖、掃描圖與轉錄的版權處理。 | 未取得使用權不得收錄受版權保護掃描、原始圖像或大段逐字轉錄；來源頁只存引用 metadata，不鏡像內容。 |
| 發布治理 | 「人工 Review／發布」沒有責任人、版本與回滾規則。 | 每次資料變更先跑本機檢查，再由人工審核來源與說明；以 Git commit/標籤保留版本並可回滾。 |

## 建議後續決策（不在 v0.1 自動假定）

1. 確認 `region` 是否改為更精確的發售版枚舉（例如 JP / NA / EU）而非 ISO 格式。
2. 決定是否將 `sourceIds` 升級為有頁碼／章節欄位的 `citations` 物件陣列。
3. 為多語原文、繁中翻譯、譯名別名與術語表訂定欄位及審稿規則。
4. 決定圖片的授權紀錄、檔名規則、alt text 與資料來源的關聯模型。
5. 定義「全流程／100%」的可衡量完成門檻，以及不同地區版差異的處理策略。
6. 決定是否加入 Service Worker。v0.1 不加入，以免快取更新與 `file://` 相容性問題未被妥善治理。

## v0.1 驗收基準

- 所有示範內容均明示為 placeholder／demo，且不聲稱真實遊戲條件。
- 各資料檔可透過 `scripts/validate-data.js` 驗證必要欄位、enum、日期、重複 ID 與來源參照。
- 各 HTML 頁有標題、主內容 landmark、導覽與內部連結。
- 網站不載入外部 CDN 或遠端資源；桌面與手機版共用同一套靜態資產。
- 有待研究、衝突或未查證內容時，網站與資料層均優先顯示其狀態，而不是推測。

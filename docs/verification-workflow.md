# 查證與發布流程

1. **蒐集**：依來源政策收集候選資料，先登錄 `sources.json`，不先寫成事實。
2. **轉錄與區隔**：標明 Dreamcast / PS2 版本、地區與可定位引用。
3. **交叉驗證**：優先以獨立可靠來源比對；衝突保留雙方說明。
4. **撰寫**：填寫共通欄位、專屬欄位與 `verificationNote`。未知可保留 `null`，不可臆測。
5. **機器檢查**：執行 `npm test`、`npm run validate:data`、`npm run check:links`、`npm run check:js`。
6. **人工審查**：人工打開來源、確認引用定位、版本區隔、繁中譯文和劇透標示。
7. **發布**：只發布通過檢查與人工審查的變更；以 Git commit／tag 保留可回滾版本。
8. **維護**：來源失效或新證據出現時，更新 `lastVerified`、狀態和備註；歷史衝突不可悄悄覆寫。

## 最低發布門檻

每頁至少有一個來源、版本、查證狀態及更新日期；無 JavaScript 錯誤；桌面與手機基本檢查通過；所有新增資料均可被 schema 與來源參照檢核。
